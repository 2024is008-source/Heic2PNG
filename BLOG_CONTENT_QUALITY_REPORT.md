## Research, factual corrections and limits

- **Windows Photos:** Microsoft’s [HEIF/HEVC guidance](https://support.microsoft.com/en-us/windows/apps/photos/photos-app-video-editor-error-can-t-view-this-file-type) is explicitly scoped to a legacy Windows 10 Photos/Video Editor workflow. It does not establish universal Windows 11 PNG export menus, a fixed shortcut or a batch restriction. Those unverified assertions were removed. The native path now requires the installed app to open the file and explicitly offer PNG; otherwise the reader is directed to the browser workflow.
- **Windows cloud downloads:** Apple documents [keeping iCloud photos downloaded](https://support.apple.com/en-gb/guide/icloud-windows/-icw524278130/icloud). The article no longer diagnoses a placeholder solely from small file size or treats a PowerShell size listing as image validation/conversion.
- **Mac export:** Checked [Preview conversion and batch selection](https://support.apple.com/guide/preview/convert-image-file-types-prvw1012/mac), [Preview grouped-window settings](https://support.apple.com/en-ie/guide/preview/prvw1085/mac), and [Photos selected-format export](https://support.apple.com/guide/photos/export-photos-videos-and-slideshows-pht6e157c5f/mac). Menu guidance stays version-dependent and distinguishes a PNG export from an unmodified original.
- **iPhone capture/downloads:** Checked [Apple HEIF/capture guidance](https://support.apple.com/en-us/116944) and [download locations](https://support.apple.com/en-us/102440). Camera preference changes are separated from converting older files, and Safari/Files download selection is explained.
- **Browser requirements:** [MDN OffscreenCanvas export](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/convertToBlob) describes browser API support; [MDN image formats](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types) describes display support. These do not prove that an upload form accepts AVIF or that every HEIC file converts. Local worker/client code confirms this site uses its own decoder, browser workers/canvas, and a 60-megapixel input guard.
- **Image quality:** Checked the [W3C PNG specification](https://www.w3.org/TR/png-3/). Lossless PNG encoding is kept separate from whole-source preservation; no fixed compression ratio, universal quality setting or complete HDR/ICC/auxiliary preservation is promised.
- **Legacy Windows support:** Retained the lifecycle caveat after reviewing [Microsoft Windows 10 release information](https://learn.microsoft.com/en-us/windows/release-health/release-information). Local image extensions do not extend OS support.

This was source review and local site verification. No physical Mac/iPhone or Windows Photos workflow was executed. Browser tests cover this site’s UI and generated content, not hands-on verification of every OS menu or every browser/device combination. The existing queue artwork is explicitly labelled an illustration rather than a screenshot.
